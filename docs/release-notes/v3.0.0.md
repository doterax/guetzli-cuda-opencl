## guetzli-cuda-opencl v3.0.0

A rewrite of the code base (C++20, CMake, injected backends instead of global modes) together with a round of GPU
correctness fixes and speedups. Some outputs change slightly because real encoder bugs were fixed; see "Output
changes" below.

### Highlights

- **The OpenCL backend works on real images again.** v2.2.6 `--opencl` wrote images of a few KB for photos (for
  example 47 KB instead of 2.9 MB for a 12 MP photo). OpenCL and CUDA now agree with each other and with the CPU
  encoder.
- **CUDA on more GPUs, without a long first run.** The binary embeds native code for Pascal through Ada (sm_61, 75, 86,
  89) and compute_52 PTX for everything else. Maxwell and Pascal GPUs can use the CUDA backend (before: silent fallback
  to OpenCL), and the first run no longer spends 7–30 s JIT-compiling the kernels (issue #15). If the kernels still do
  not load, the message names the driver version, the device and the JIT log.
- **GPU errors fall back to the CPU.** A failing GPU call no longer aborts the process: the image is encoded on the CPU
  instead, with one message that names the error.
- **Faster.** The GPU no longer round-trips images and distance maps through the host, buffers are pooled, kernels are
  no longer followed by a sync each, and the entropy-code updates on the CPU are cheaper. Output is unchanged by these
  speedups. Against v2.2.6 on an RTX 3060 Laptop GPU: a 12 MP photo with `--cuda` 35.0 s -> 20.9 s, a 1 MP PNG with
  `--cuda` 9.7 s -> 6.0 s and with `--c` 65.1 s -> 44.3 s.
- **`--check`** (`--checkcl`, `--checkcuda`) compares the GPU and CPU result per stage, runs about as fast as `--c` and
  writes exactly the `--c` output.

### Output changes

- 4:2:0 output: frequency masking applied changes meant for chroma block (x, y) to block (x/2, y/2) (bug since 2025).
  Fixed; 4:2:0 outputs get smaller (photos -0.4 % to -1.8 %).
- Frequency masking: trailing blocks without zeroing candidates got a bogus one from an earlier block, so a coefficient
  could be zeroed that was never scored for that block (bug since 2017). Fixed; outputs change by a few bytes.
- TIFF with alpha: alpha was read from the wrong byte and blended twice. It is now composited correctly on black or
  white, also for gray + alpha. Opaque TIFFs are unchanged. PNG with partial alpha is blended correctly on white.
- GPU block zeroing read the original JPEG's coefficients with the output image's block width (wrong for 4:2:0 inputs
  with MCU padding), and CUDA misread its block geometry: CUDA output now matches OpenCL.
- CUDA computes its host-side butteraugli constants like OpenCL (in double); CUDA distances can differ from v2 in the
  last digits.
- Linux CPU path: float math uses the float overloads as on Windows, so Linux output may differ slightly from v2 and
  now matches Windows.
- Builds without OpenCL and CUDA use the same optimized comparator as `--c` in a GPU build (they used the reference
  comparator and gave different output). Release binaries are not affected.

### Command line and messages

- New `--backend auto|cpu|opencl|cuda`, `--check` and `--help` (CLI11). The old flags (`--c`, `--opencl`, `--cuda`,
  `--checkcl`, `--checkcuda`, `--auto`) still work; the last one given wins.
- Invalid numbers are rejected instead of being read as 0; `--memlimit` below -1 is rejected.
- Exit codes: 0 success, 1 usage or I/O error, 2 input is not PNG/TIFF/JPEG, 3 input could not be processed (corrupt
  data, memory limit, encoder failure). Before, every failure printed "Unknown file format" and exited with 2.
- A damaged JPEG is reported as such; the memory-limit message names the limit and `--memlimit` / `--nomemlimit`;
  JPEGs decoded through libjpeg-turbo report decoding errors and exit with 3 (before: exit code 1, or libjpeg ended
  the process).
- Asking for a GPU backend that is not compiled in prints the CPU-fallback message.
- `--verbose` also prints the OpenCL device report, the CUDA module load time and the CUDA memory-pool statistics
  (the pool line is no longer printed on every CUDA run).
- `--check` lines have a new format: `CHK <stage> <part> <count>:<size> (max diff <d>)`.

### Platform and packaging

- Windows: built with MSYS2 UCRT64 and linked against the Universal C Runtime. Windows 10 and 11 include it; Windows 7
  SP1 and 8.1 need KB2999226 (see README, "Windows runtime"). The executable imports only system DLLs; CUDA and
  OpenCL are loaded at run time, so it starts on machines without GPU drivers.
- Release executables are stripped (the Windows exe is 6.8 MB including the 1.6 MB CUDA fatbin).
- Building: CMake + Ninja (`cmake --preset release`), binaries in `build/<preset>/bin`; the Makefile is gone. See
  BUILD.md.
